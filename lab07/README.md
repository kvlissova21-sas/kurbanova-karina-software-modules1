Задание 2. Чтение линейной блок-схемы

Входные данные: a, b 
Выходные данные: S и P
Тестирование при a = 4 b = 7. S = 4 * 7 => S = 28; P = 2 * (4 + 7) => P = 22

Задание 3. Чтение ветвлений
Алгоритм находит наибольшее из двух чисел a и b и выводит его.
Проверка для пар:
(9; 4): число a (9) > чем b (4) => «Да» => m = a = 9;
(-3; 2): a (-3) < b (2) => «Нет» => m = b = 2;
(5; 5): a (5) = b (5) => «Нет» => m = b = 5. 
При замене условия a > b на a ≥ b в последнем тесте ветка изменится на «Да», но результат не поменяется, тк они равны. 
Задание 4. Чтение цикла
Трассировку при N = 4:
S = 0; i = 1; i (1) ≤ N (4) => «Да» => S = 0 + i (1) =>
S = 1; i = 2; i (2) ≤ N (4) => «Да» => S = 1 + 2 => 
S = 3; i = 3; i (3) ≤ N (4) => «Да» => S = 3 + 3 =>
S = 6; i = 4; i (4) ≤ N (4) => «Да» => S = 6 + 4 =>
S = 10; i (5); i (5) ≤ N (4) => «Нет» => Вывод S
Количество выполнений тела цикла = 4
Проверка при N = 1:
S = 0; i = 1; i (1) ≤ N (1) => «Да» => S = 0 + i (1) =>
S = 1; i = 2; i (2) ≤ N (1) => «Нет» => Вывод S
Проверка при N = 0:
S = 0; i = 1; i (1) ≤ N (0) => «Нет» => Вывод S
S — это накопитель суммы. Начальное значение суммы равно нулю, чтобы при первом прибавлении получить 0 + i = i
i — это счётчик цикла. Задаёт первое число, которое будет прибавлено к сумме.
Цикл завершается потому, что счётчик i увеличивается на каждом проходе и рано или поздно превысит N.
 
Задание 5. Поиск и исправление ошибок
Случай А: Ошибка 1: ввод a, b в прямоугольнике вместо параллелограмма
Последствие: Ввод неотличим от вычисления
Исправление: Заменить прямоугольник на параллелограмм;
Ошибка 2: вычисление S в параллелограмме вместо прямоугольника
Последствие: Вычисление выглядит как ввод/ вывод
Исправление: Заменить параллелограмм на прямоугольник; 
Ошибка 3: нет стрелки между P ← 2 · (a + b) и Вывод S, P.
Последствие: неясен порядок выполнения
Исправление: добавить стрелку; 
Случай B: Ошибка: ветви «Да» и «Нет» перепутаны.
Последствие: алгоритм находит наименьшее число вместо наибольшего.
Исправление: по «Да» → m ← a, по «Нет» → m ← b.
Случай C: Ошибка: удалён блок i ← i + 1.
Последствие: при N ≥ 1 цикл бесконечный, S бесконечно растёт; при N = 0 цикл не выполняется, алгоритм завершается корректно.
Исправление: добавить i ← i + 1 после S ← S + i.
Случай D: Ошибка: удалён блок S ← 0.
Последствие: S не имеет начального значения, выражение S ← S + i нельзя вычислить.
Исправление: добавить S ← 0 перед циклом.
Контрольные вопросы:
1.	Для чего используется блок-схема?
Ответ: Блок-схема используется для наглядного представления алгоритма. Она показывает последовательность действий и порядок переходов между ними с помощью геометрических фигур и стрелок, что позволяет читать алгоритм, определять порядок выполнения шагов, вручную проверять его работу и находить ошибки в графическом представлении.
2.	Как обозначаются ввод, вычисление и условие?
Ответ: Ввод / вывод: параллелограмм, Ввод a, b;
Вычисление: прямоугольник, S ← a + b
Условие: ромб, a ≥ b?
3.	Чем присваивание отличается от проверки равенства?
Ответ: Присваивание (S ← a + b) — это действие. Оно вычисляет выражение справа и записывает результат в переменную слева, заменяя её старое значение.
Проверка равенства (a > b) ?— это вопрос, который не меняет значения переменных. Он лишь определяет, по какой ветке («Да» или «Нет») пойдет дальнейшее выполнение алгоритма.
4.	Чем следование отличается от ветвления?
Ответ: Следование — действия выполняются последовательно, одно за другим. Все блоки проходятся по порядку. 
Ветвление — после проверки условия выполняется только одна из нескольких ветвей.
5.	Может ли тело цикла с предварительной проверкой не выполниться ни разу?
Ответ: Да, может. В цикле с предварительной проверкой условие проверяется до выполнения тела. Если условие сразу ложно, тело цикла не выполнится ни разу.
6.	Для чего задают начальное значение накопителя?
Ответ: Начальное значение накопителя задают для того, чтобы было с чем выполнять первое сложение.
7.	Что может произойти без изменения счётчика цикла?
Ответ: Если счётчик цикла не изменяется, то: условие цикла может оставаться истинным бесконечно; цикл зацикливается; алгоритм никогда не завершается; результат не выводится.
8.	Почему нужно проверять случай равных чисел?
Ответ: Выбранная ветвь меняется в зависимости от того, используем мы ≥ или >. При a = b условие a ≥ b истинно, а a > b ложно. 
9.	Что показывает таблица трассировки?
Ответ: Таблица трассировки показывает пошаговое выполнение алгоритма: какой блок выполняется на каждом шаге; какие значения принимают переменные; каков результат проверки условия; куда идёт переход.
10.	Почему успешной проверки на одном примере недостаточно?
Ответ: Потому что один пример не покрывает все возможные случаи.
